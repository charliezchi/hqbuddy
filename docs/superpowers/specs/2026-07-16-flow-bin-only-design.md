# hqbuddy `-flow -bin_only` Design

## Goal

Add a `-flow -bin_only` mode to `hqbuddy` that produces a trimmed-down TCL script from the normal `-flow` output. The script keeps the implementation flow (synthesis → pack → place → route → bitgen) but suppresses all intermediate file writes (`.v`, `.xpn`, `.rpt`), leaving only the final bitstream generation step. The output bitstream name can be specified by the user.

## Motivation

The normal `-flow` TCL generates many intermediate files (RTL netlist, XPN after pack/place/route, timing reports) that are useful for debugging but slow down runs when only the final bitstream is needed. A bin-only mode speeds up batch builds and reduces disk clutter.

## CLI

```text
hqbuddy -flow [<.hqprj>] -bin_only [<name>] [-o <file>]
```

- `[<name>]`: optional user-specified base name for the final bitstream. If omitted, the original `design.bitgen` target produced by `hqprj2tcl` is kept.
- `-o <file>`: optional output TCL file name (same behavior as normal `-flow`).

Examples:

```text
hqbuddy -flow test.hqprj -bin_only firmware
hqbuddy -flow test.hqprj -bin_only -o build.tcl
hqbuddy -flow ddrc_native_demo.hqprj -bin_only
```

## Behavior

1. Generate the full flow TCL with `hqprj2tcl`, exactly as normal `-flow` does.
2. Post-process the generated TCL:
   - Remove lines that write intermediate files:
     - `nl.write ...`
     - `nl.report ...`
     - `xpn.write ...`
     - `ta.report ...`
     - `ta.fmax.report ...`
   - Keep all implementation commands:
     - `design.analyze`, `design.rtlsyn`, `design.tdomap`, `design.flatten`
     - `design.pack`, `design.place`, `design.route`
     - `design.bitgen ...`
   - If a name was provided, replace the target in the final `design.bitgen <original>` command with `<name>.<ext>`, where `<ext>` is the extension used by the original command (`bit` or `bin`). Any extra arguments after the original target are preserved. If no name was provided, the original target is kept unchanged.
3. If `-o` is omitted, write the result to the default `run_hqprj.tcl` in the project directory.
4. Print a confirmation message with the generated TCL path.

## Implementation Plan

### `hqbuddy/flow.py`

Add two functions:

- `_make_bin_only_tcl(full_tcl_path: str, bin_name: str | None = None) -> None`
  - Read the full TCL generated by `hqprj2tcl`.
  - Filter out intermediate-file commands.
  - Locate `design.bitgen`, extract the original extension, and rewrite the target name when `bin_name` is provided.
  - Overwrite `full_tcl_path` with the trimmed content.

- `run_flow_bin_only(hqprj_path: str, bin_name: str | None = None, output_tcl: str | None = None) -> None`
  - Validate the `.hqprj` file exists.
  - Generate the full TCL via `hqprj2tcl` using `_generate_temp_tcl` and `_run_hqfpga`.
  - Determine the output TCL path (use `output_tcl` or default to `run_hqprj.tcl`).
  - Call `_make_bin_only_tcl` to trim it.
  - Clean up the temporary TCL.

### `hqbuddy/__main__.py`

- Update `show_help()` to list `-bin_only` under `-flow`.
- Update `cmd_flow()` to recognize `-bin_only <name>` before delegating to `run_flow_bin_only`.
- Import `run_flow_bin_only` from `hqbuddy.flow`.

### Error Handling

- If the output TCL is not generated by `hqprj2tcl`, print an error and exit.
- If no `design.bitgen` line is found, print an error and exit.

## Trade-offs

This implementation uses simple line filtering rather than parsing the TCL into an AST. It is:

- **Pros:** Easy to understand, matches the existing looptdo post-processing style, and robust against minor changes in `hqprj2tcl` output formatting as long as command names remain stable.
- **Cons:** Relies on specific command names (`nl.write`, `nl.report`, `xpn.write`, `ta.report`, `ta.fmax.report`). If `hqprj2tcl` introduces new intermediate-file commands, they must be added to the filter list.

## Future Considerations

- If `hqprj2tcl` ever produces `.bin` outputs instead of `.bit`, the extension auto-detection will adapt automatically.
- The filter list can be extended if additional intermediate-file commands are identified.
