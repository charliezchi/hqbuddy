# hqbuddy 自回归迭代框架（Round 21+）

> 2026-09-14 制定。R1-R20 已把 insight 推到"指哪儿打哪儿"收官标准（见
> blind_eval_log.md 总账）；本框架把那 20 轮的临时做法固化成可持续循环：
> **每一轮的输出（发现/修复/认知）自动成为下一轮输入的一部分**，直到所有
> 能力轨道进入维护态。环境变化（HqFPGA 升级 / 新板 / hqbuddy 大改）会自动
> 把相关轨道踢回活跃态。

## 1. 目标函数（什么算"更好"）

**总目标**：hqbuddy 成为 HqFPGA 全流程的 agent 可信 CLI 代理——GUI 能做的它
都能做（或明确告知做不到且给出替代路径）；板上行为可预测、可验证、可自证。

分能力轨道，各有验收线（bar）：

| 轨道 | 范围 | 验收线 |
|---|---|---|
| T1 insight 在线调试 | 触发/抓波/VCD/信号增删改 | 触发值严格满足条件；VCD 可递推验证；错误路径清晰无副作用 |
| T2 VIO 运行时探针 | 生成/登记/读/写/轮询 | 读位级精确；写生效；异常输入友好报错 |
| T3 工程生命周期 | new_prj/add/build/report/clean/device/SoC | 报告数字与原始报告逐字一致；产物校验不漏报 |
| T4 GUI 等效性 | GUI 能力 ↔ CLI 覆盖矩阵 | 每个 GUI 功能：CLI 有等价命令，或文档载明"仅 GUI"+替代路径 |
| T5 文档与 skill | README / skill references / boards | agent 只靠 skill 就能走通全流程；无未记载参数 |
| T6 板卡事实库 | boards/*.md | 新板录入即查即用；板级事实与实测一致 |

## 2. 自回归循环（每轮 R(n) 做什么）

```
任务池(按优先级) ──→ R(n) 计划 ──→ 盲评执行 ──→ 三线评价 ──→ 反馈分流 ──→ 落账
   ↑                                                        │
   └────────────── 修复项回流任务池（优先级最高）←──────────┘
```

1. **计划**：从任务池选一个主题，写 3-5 个用例，**判据先于执行写下**
   （R2 教训：不能拿"触发得快"当"触发值正确"）。
2. **盲评**：子 agent 独立执行，真实板卡操作；不向其泄露预期结论。
3. **评价**（三线，见 §3）。
4. **反馈分流**（见 §4）。
5. **修复→复验**：每个修复必须带一个复验用例，且在后续轮重演原用例后才可关闭。
6. **落账**：blind_eval_log.md 追加 Round 条目；本地 commit。

## 3. 评价系统

三线评分，逐轮记录：

- **L1 无板自检**（每轮必跑，几分钟）：python 单测；`-init` 前置体检；幂等性。
- **L2 板上确定性实验**（需要板）：用可证明的设计（计数器/LFSR/移位环），
  校验"触发点信号值严格满足条件 + VCD 全样本递推成立 + clock_cycle 零缺口"。
- **L3 盲评判读**：子 agent 独立判读；全链路轮用 125 分制（R1 先例）。

**回归集**（任何"修复/新功能/升级"合入前必须绿）：
- `hqbuddy -insight -selftest`（确定性计数器：下载→布防→抓取→1024 样本校验）
- R16 六条触发矩阵（BOTH 折叠/RANGE_C/NOT/跨信号 AND/电平/诚实超时）
- R11 错误路径矩阵（model 校验/单采样时钟/矛盾折叠/NE 不可表达/sample 拒绝）

**结果分级**：
- S0 数据错误（报数字错、触发值假命中、产物漏报）→ 停止新功能开发，立即修
- S1 功能缺失（GUI 有 CLI 无、命令缺参数）
- S2 体验问题（报错不清晰、缺补救指引）
- S3 认知修正（硬件限制、板级事实——记文档不改代码）

## 4. 反馈系统（发现往哪流）

| 发现类型 | 流向 |
|---|---|
| 可修缺陷 S0/S1/S2 | TODO.md 修复清单 + 复验用例编号 |
| 新认知/硬件限制 | skills/hqfpga/references/*.md + blind_eval_log.md |

## 5. 板卡交互协议（每轮前置检查 + 板上纪律）

1. 前置：`hqbuddy -root`（版本就绪）→ `hqbuddy -cable --detect_model`（板在线 +
   拿 model）→ `--model` 与实际板一致性由工具强制（双板共缆教训）。
2. 下载一律 `-cable --sealion <bin> --model <model> --Burst`；下载属 RAM 加载，
   **重下 bit = 设计复位**（卡死稳态的第一处置）。
3. 板况异常判定特征：数据通道恒值 + clock_cycle 在走 + 触发与条件无关 →
   先重下 bit，再怀疑工具。
4. JTAG 槽互斥：VIO 与 LA 不能同 bit（PHY-PLA-665）；DDR 类设计下载后 1~2 分钟
   训练期，涉训练期状态要立即布防。
5. GUI 开着时不得用 CLI 改工程（GUI 保存会以内存态覆盖磁盘）。
6. 触发判定用窗口（trig-1 ~ trig+8），不取单点；不可满足条件允许诚实超时。

## 7. 节奏与退出条件

- 节奏：一个会话一轮；一轮一个主题；3-5 用例；修复项优先插队。
- 轨道退出（转维护态）：连续 2 轮无新 S0/S1 且回归集全绿。
- 维护态轨道被以下事件踢回活跃态：HqFPGA 版本升级（强制回归集）、新板接入、
  hqbuddy 结构性改动。
- 全部轨道维护态 = 周期性静默回归（低频跑回归集），直至下一次环境变化。
